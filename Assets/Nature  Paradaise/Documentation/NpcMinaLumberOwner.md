# Mina and Lumber Store owner

Mina's reusable visual is `Resources/Characters/Mina.prefab`. Its evaluated idle height, including the hat, is approximately 1.5 m, matching `PlayerDimensions.Height`. The original Toon Farm character already has a skinned Humanoid skeleton and valid Avatar. Keep that Avatar: copying the player's skeleton over its skin weights is unnecessary and would break the model. `Mina Actions.asset` reuses the player's existing shared Humanoid Idle/Walking copy; the gameplay player remains Generic so horse/tool bindings are preserved.

`NPCCharacterMotion` plays idle and chooses walking from actual world displacement, with walking playback speed following movement speed. It does not add player controls, root movement, a patrol route, or scan for the player each frame. The component can support a future route/AI moving Mina's root. Pause freezes the animation, and disabling the character releases its playable graph.

Existing Map Mina is upgraded by `DialogueTrigger.Awake` for `npc.mina.test`. Her old giant visual is replaced, the capsule becomes 1.5 m high/0.24 m radius, and her position, quest ID and conditional conversations remain intact. The editor narrative setup creates the same animated visual for new fixtures. No Map rebuild is required. The visual installer is **Nature Paradise → Narrative → Apply Animated Mina**.

Every Lumber `UpgradeShopFront` now creates one `LumberStoreOwner` at its existing editable departure point, grounded with the same safe-position search as departing jobs. It uses `BuilderDedicated.prefab`, its own Avatar, and the construction profile's 0.75 metre calibration, approximately 1.5 m tall. Editable model source remains `ArtSource/Builder_Worker/Blender/Builder_Humanoid.blend`. No extra model or textures are loaded for a different shopkeeper. The former `Seller_Capsule_Editable` placeholder is hidden.

The owner disappears from the shop when the first paid project dispatches, walks to the site using the existing obstacle-aware path, performs construction work, then walks back before becoming available again. Additional paid projects wait, with no extra visible builder and no work credited while queued. Store menus and free-construction debug remain available; free orders still follow the real worker process. House upgrades, new PropertySite structures, and existing BuildingSite upgrades all share `ConstructionProject.Begin`.

Saved jobs include the stable store hierarchy identity, persistent queue order and suspended phase. `Queued` is appended to the saved phase enum; all previous values remain unchanged. Old jobs without owner fields adopt the nearest Lumber Store and retain progress. Returning builders remain saved even after the building has completed. Restoring jobs in a different iteration order preserves the queue. If there is no Lumber Store in an isolated scene, the original standalone worker fallback remains usable.

Validation: native Unity Play Mode verified Mina's evaluated height (1.4999 m), grounding, one skeleton, idle and walking, preserved dialogue, one visible owner, travel/arrival, queue and work accounting, JSON restore in reverse order, completion once, return-trip restore, old saves, and actual house-upgrade dispatch/restore. Main scene and user saves are not used by the test fixture. Evidence is locally under `ArtSource/NpcOwners`.

Mesh measurements use scale-compensated `SkinnedMeshRenderer.BakeMesh(mesh, true)` before transforming vertices to world space, avoiding counting renderer scale twice ([Unity reference](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/skinnedmeshrenderer/bakemesh)).
