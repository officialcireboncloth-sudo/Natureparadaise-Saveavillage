# Tool targeting and automatic approach

One tool input captures the target shown on the last visible world prompt. A newer proximity scan cannot replace that target or discard the input merely because a different object became closest. Resource selection also filters for the equipped tool and the same floor.

`PlayerToolApproach` is added on demand to the player. It checks the actual horizontal work reach and an unobstructed work line. Work requests are capped at a 0.75m visible gap; animal side poses may request a closer position. A target already in reach starts immediately. Otherwise the player walks through the normal CharacterController collision path at the player's normal walk speed (1.2m/s by default), with the same carry/fatigue modifiers, until the captured target is reachable. The tool action then revalidates its existing item, level and stamina rules. Item consumption, drops, field updates and particles still occur at the existing animation contact.

Supported actions include sickle grass/dead crops/terrain patches, hammer rocks, axe trunks/stumps, pulling weeds, hoe, watering, fertilizer, crop booster, planting, hand harvest, manure collection, brushing, milking and shearing. The keyboard action and mobile use button share the same entry points. Repeated mobile requests during approach do not queue a second action.

The sickle prompt stays `F: Sabit`. Approach is silent: no approaching label or substitute prompt appears while walking. Its base blade/cutting radius is 0.75m in world space; approach also stops within 0.75m. Upgrades may extend the fan, while the player still approaches closely. A nearby target already in the forward fan preserves the broad sweep. A side target outside the fan is faced before the sweep begins. The 120-degree fan, contact order and real-blade trail remain shared with the animation.

The interaction's actual collision displacement supplies walk mode and animation cadence once per frame. The normal locked controller no longer writes an idle blend over it. Grounded state from the gravity move survives the horizontal interaction move, so walk cadence is not accidentally reset to 1 or changed to an airborne pose. A blocked step animates its actual zero movement.

The approach has one movement lock and one arrival callback. Manual WASD/joystick steering, jump/cancel input, changing the held item/tool, Tangan Kosong, target removal, owner disable, a modal/foreign movement lock or an unreachable path cancel pending work. Clock pause freezes walking and its timeout. Cancellation releases only the approach lock and any temporary target reservation; it does not consume tool stamina or items. Normal manual movement retains its own stamina rules.

Movement is bounded to a short local approach (default maximum 4m, 6 active seconds). Solid obstacles are respected. An obstructed work line cannot trigger a tool through a wall, and lack of progress cancels with feedback. The approach does not teleport the player through an obstacle. Animal care reserves the animal's routine while walking to its side working position; cancellation releases the reservation, and the normal care action takes over on arrival.

No scene editing or save schema change is needed. Loading a validated save cancels pending approach callbacks and reservations before restoring world state. The player uses a bounded non-allocating work-line query; world targets need no extra approach Update or navigation component. Existing gatherable, tree, field and manure save data remain authoritative.

The closer/silent approach revision passed 51 native approach/gameplay checks. The measured work gap was 0.75m, with normal walk speed, stable walk blending, grounded cadence matching actual displacement, cancellation, field save/load and animal tools. Sickle regression checks cover physical blade contacts, fan limits, ribbon rendering, dead crops and real terrain detail patches. The main Map was not opened or saved for this work.
