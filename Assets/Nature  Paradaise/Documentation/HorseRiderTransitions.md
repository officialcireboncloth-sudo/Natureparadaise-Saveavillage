# Horse mounting, saddle alignment and dismounting

The authoritative editable player is `Source~/Player/Player_Farming.blend`. It contains the native player mesh and control rig plus all 47 player Actions. Horse movement follows the approved AnimatedPreview_v2 mannequin, including forward/left body lean, the corrected supporting left knee, and the nearly straight right-leg sweep over the rear of the saddle. Left and right takes are authored explicitly for the Generic rig.

The five horse clips now come from the complete `mesh/Dummy/PlayerDummy/Player.fbx`: Mount Horse, Mount Horse Right, Dismount Horse, Dismount Horse Right, and Riding Idle. The older animation-only RiderHorseTransitions.fbx and Source~/HorseRider files are historical sources; the live profile, animation set and controller no longer use them.

Horse Companion.prefab has a SaddleSeatAnchor under TFP_Horse_01A/RIG_Horse_01/Root/Def_Hip/Def_Spine. It represents the saddle surface. PersonalAnimal aligns the rider pelvis to that marker plus a fixed 0.05 m anatomy offset in LateUpdate. Horse scale is not forced to a fixed adult size, and the rider keeps its original world size. The marker follows the animated spine, so mount end, seated idle and dismount start share one reference.

Horse Rider Transitions.asset stores the paired world trajectory from Source~/Player/HorseTrajectory.json. Mount end, riding idle and dismount start share the same pose; standing endpoints match the production Idle. Runtime progress follows the actual Animator normalized phase, including entry blends and pause. Mount/dismount action speed is 2.5, giving durations of about 2.2 and 2.4 seconds. Player colliders and held-tool poses are suspended during transitions and restored after dismount.

Dismounting checks both sides and nearby forward/back alternatives using the player capsule. It rejects obstacles, large height steps and drops. If both sides are blocked the player remains mounted with bottom-panel feedback. Disabling a horse during a transition restores player movement, collider states and Animator speed.

For repeat exports, save the complete master and run its embedded **Export Player to Unity.py** text, or run the adjacent export_player.py with Blender. It bakes the saved Actions without rebuilding poses, excludes the reference horse and preview-only object movement, preserves the production hierarchy and hidden rig meshes, and reloads the intact master afterward. In Unity run **Nature Paradise > Animals > Apply Horse Rider Transitions** to refresh take ranges, references and the matching trajectory. Keep HorseTrajectory.json paired with the authored world preview when changing the trajectory. PlayerVisualSetup retains these clip overrides on future rebuilds.

The original external Player_Farming.blend location is no longer present.
